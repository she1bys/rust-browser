How a small browser keeps its memory low

This page is part of the Rust Browser test site. It exists so the automated tests can check that reader mode finds the article, copies its text, and leaves the menus, sidebars and footers behind.

A web browser spends most of its memory on the pages it shows. Every open tab runs scripts, keeps images decoded, and holds the layout of the page ready to draw. A lightweight browser therefore saves the most by doing less work for tabs that are out of sight, and by not loading things the reader never asked for.

Freezing and sleeping tabs

When a tab has been in the background for a while, its scripts can be paused without losing anything. The page looks exactly the same when you come back to it. After a longer time, the tab can be put to sleep entirely, which frees all of its memory; it simply reloads the next time it is opened.

Tabs that are playing sound, downloading a file, or showing something on screen are never paused, because the person using the browser would notice straight away. Good defaults matter more than clever settings, since most people never open the settings page at all.

Blocking what nobody asked for

Advertising and tracking scripts are often a large part of what a page downloads and runs. Blocking them at the network level means they are never fetched, never parsed and never executed, so pages appear sooner and use less memory and battery. The trade-off is that a few sites expect those scripts, which is why the blocker can be turned off with a single switch.

The fastest code is the code that never runs.

Finally, the browser itself should stay small: a few megabytes for the program, a single shared engine for all tabs, and helper windows that are only created when they are actually used. Each of these choices is modest on its own, but together they make the browser comfortable on older and smaller computers.
